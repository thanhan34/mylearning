PR2B.2A emulator persistence verification remains deferred by administrator decision.
No Firebase adapter, Admin initialization, credentials, API/UI integration, deployment,
Rules changes, migration, or actual dual-write is included. Do not deploy this core as
a complete writer. Existing unrelated working-tree changes are not part of this PR.

## Protocol

- Caller supplies generation, unchanged source document ID, stable operationId and
  expectedRevision. Supported intents: create full source, shallow update patch with
  explicit top-level unset list, delete. Dotted update keys are literal top-level keys,
  not SDK field paths. No implicit ID normalization, retry rebasing or role repair.
- Snapshot request through the PR2B.1 codec once before callback retries. All business
  projection/approval/search comes from PR1; use PR2B.2A precheck before grams.
- Inside callback read users/id, generation entry, state, summary, in that order,
  before any write. Summary must explicitly be ready with matching generation,
  schemaVersion=1, codecVersion=1 and structurally coherent nonnegative counts.
- A live state must match the source canonical hash, regenerated projection hash,
  decoded entry and contribution. A tombstone requires absent source/entry and null
  hashes/contribution. Missing state with an existing source OR entry is an error,
  never oldContribution=0. Only an entirely absent account can start revision zero.
- Validate latest receipt before expectedRevision. Identical operationId AND request
  hash returns duplicate with no writes. Same ID/different intent rejects. Only the
  most recent operation receipt is retained: older retries with their original
  expectedRevision are rejected, not replayed. This is not a permanent idempotency
  ledger; clients must never recycle operation IDs for different intents.
- Require expectedRevision exactly equal to current revision. Revision increments on
  every accepted mutation, including a same-value update; safe-integer overflow rejects.
  Concurrent stale mutations reject rather than silently overwrite/rebase.
- Compute contributionDelta(old state, next projection). Apply to summary with safe
  integer/nonnegative checks; zero map counts are removed. If delta is zero do NOT
  stage summary write. Summary is still read/validated, so contention can still retry.
- Stage source + encoded directory + state, and summary only when delta is nonzero.
  Delete removes source/entry and retains tombstone, revision and operation receipt.
  Recreate must use that tombstone revision and increments it, preventing ABA/double counts.
- Callback has no external I/O, logging, clock/random ID generation or mutable caches.
  All observable database effects must be published atomically by the adapter.

## Adapter contract and mock

Core imports no Firebase SDK. AccountTransactionAdapter supplies a serializable
runTransaction, detached values, missing=undefined, absent-document conflict detection,
staged writes and bounded retries. Throwing callback must discard staged mutations.
Memory adapter uses snapshots/version validation including absent/deleted paths,
copy-on-write atomic publication and synchronous commit. Injected staging failure,
commit failure, retry exhaustion and concurrent conflicts exercise rollback/retry.

Logical metrics include attempts, reads (including absent docs), staged writes,
committed writes, retries, commits and summary writes. These are NOT Firebase billed
reads/writes, latency measurements, or a model of SDK locking/network behavior.

## Fail-closed limits

- Native source subset is deliberately narrower than the codec: plain objects,
  primitive values, dense arrays without direct nested arrays. Reject undefined,
  accessors, symbols, cycles, functions, SDK classes/Timestamp, unpaired surrogate
  source strings/keys and reserved keys. Never silently strip or normalize data.
  Missing source fields remain missing. Projection codec still preserves undefined
  fields generated by the legacy view and UTF-16 semantics supported by PR1.
- Entire source is hashed/preserved including fields outside the projection. Existing
  unsupported legacy data rejects without writes, even on deletion; needs reviewed
  repair/typed source adapter policy, not a catch-and-write fallback.
- Input/codec budgets guard processing, not Firestore document/index limits. No
  production storage approval is implied; index fanout/schema and every document's
  size (source, entry, state and summary) still need validated storage guards.
- Summary shape/arithmetic checks cannot prove global correctness of preexisting
  counts. Trusted generation bootstrap and independent reconciliation are required.
- Caller selects a ready generation. There is no active-generation pointer/cutover
  fence yet. Multi-generation routing and synchronization remain integration blockers.
- Unexpected adapter errors return ADAPTER_FAILURE, not evidence of no remote commit.
  Mock rejection guarantees rollback; a future network adapter must handle ambiguous
  commit outcomes via operation receipt/revision reconciliation before retrying intent.
- In-process trusted data only: JavaScript Proxy traps are outside codec guarantees.

## Verification and rollout gates

Run `node scripts/test-account-transaction.cjs`, all `scripts/test-*.cjs`,
`npx tsc --noEmit --incremental false`, and `git diff --check`.
Tests cover create/update/delete, legacy/explicit approval, name/feedback types,
role changes, zero delta, duplicate/reused IDs, retry/exhaustion, concurrent same and
different accounts, atomic rollback, missing/corrupt state/summary/entry, tombstone
recreate, codec/hash/search parity and overflow/unsupported rejection.

Before API/production: real emulator set/get and transaction conflict/atomicity tests;
reviewed real SDK adapter and ambiguous commits; inventory ALL source writers;
generation activation fencing; reviewed bootstrap/reconciliation; exact storage/index
limits; supported Timestamp/legacy source policy; authorization and audit policy;
contention/load testing of shared summary; operational rollback/recovery approval.
PR2B.3 is not started.
